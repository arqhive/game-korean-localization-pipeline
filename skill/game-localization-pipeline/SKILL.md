# 게임 한글화 파이프라인

여러 기종(3DS·NDS·GC·Wii·Wii U·SFC)의 한글화를 AI와 진행하며 다듬은 순서다.
각 단계에서 **만들 것**과 **사람에게 확인받을 곳(게이트)**이 정해져 있다. 게이트에서는 멈추고 사용자의 결정을 받는다.

## 시작할 때

0. **작업 폴더부터 정한다.** 사용자가 인자·메시지로 명시한 폴더, 또는 세션에 추가한 폴더가 대상이다. 지정이 없거나 후보가 여럿이면 추측하지 말고 묻는다. 메모리·기록에 진행 중인 다른 프로젝트가 보여도 그것을 대상으로 삼지 않는다. 다른 프로젝트 폴더의 파일은 읽기만 하고 고치지 않는다.
1. 프로젝트 폴더에 규칙 파일(`CLAUDE.md`)이 있으면 먼저 읽고 현재 단계를 파악한다. 없으면 0단계부터 한다.
2. 사용자에게 **지금 몇 단계인지** 한 줄로 알리고, 그 단계의 산출물을 만든다.
3. 게이트에 닿으면 결과를 표로 보여 주고 결정을 받는다. 결정 없이 다음 단계로 넘어가지 않는다.

## 적용 범위 정하기 (모든 게임에 똑같이 적용하지 않는다)

- 1단계 분석에서 **분야 목록**(이 게임에 실제로 있는 한글화 분야: 텍스트·폰트·그림·이펙트·3D 모델·영상·음성 자막 등 중 해당하는 것)과 **실행 환경**(배포 대상 실기·에뮬레이터, 원본을 넣는 방식)을 정해 `CLAUDE.md`에 적는다.
- 이후 단계의 검사·추출·빌드·점검은 **분야 목록에 있는 것에만** 적용한다. 해당 없는 항목은 건너뛰고 이유를 한 줄 남긴다(예: 「영상 없음」, 「폰트는 그림 글자라 해당 없음」).
- 나누는 단위(빌드를 쪼개는 단위, 점검표의 행)는 게임의 파일 구조를 따른다. 정해진 분야 이름을 억지로 쓰지 않는다.
- 게임마다 달라지는 대표적인 경우:
  - **텍스트가 전부 그림인 게임**: 폰트·창 측정 대신 그림 교체 시험으로 2·3단계를 대신한다(그림 한 장을 한글로 바꿔 띄워 보고, 그림 칸 크기를 잰다).
  - **롬 파일 하나인 구형 기종**: 교체 단위가 없으니 빌드 옵션으로 분야를 켜고 끈다. 포인터·빈 공간 부족이 주된 난관이다.
  - **3D 모델·영상·음성 자막이 없는 게임**: 해당 추출·빌드·점검을 모두 건너뛴다.
  - **화자 정보가 없는 게임**: 대사 순서와 장면으로 화자를 추정하거나 비워 둔다.

## 단계

| 단계 | Claude가 할 일 | 산출물 | 게이트 |
|---|---|---|---|
| 0 준비 | 판본 후보 비교, 원본 해시 기록, git 저장소·`.gitignore`·`CLAUDE.md` 작성 | `CLAUDE.md`, 해시 기록 | 판본 결정 |
| 1 분석 | 형식·분량·폰트 용량·압축·체크섬 조사, **무변경 왕복 재빌드 검증**, 분야 목록·실행 환경 | 분석 보고서(`references/templates.md` §1) | 진행/중단 |
| 2 출력 시험 | 초반 문구 몇 개만 한글로 바꿔 빌드 | 시험 빌드 | 배포 대상 환경에서 출력 확인 |
| 3 창 측정 | 창 종류별 한 줄 최대 폭(px)·줄 수, 넘침 검사 도구 | 창 크기 표, 검사 도구 | — |
| 4 전수 추출 | 분야 목록 전부 + 후보 목록 확인(텍스트는 화자 포함), 다른 지역판 대조 | 번역용 JSON/xlsx, 그래픽 목록, 조사 범위 표 | 조사 범위 확인 |
| 5 번역 | 용어집·말투표 먼저, 부호 규칙 적용, 태그·줄 수 검사 | 용어집, 번역 JSON | 용어집 승인 |
| 6 그래픽 | 규칙 제안 → 미리보기 → 작업 → 비교 시트 | 그래픽 규칙, 비교 시트, 목록 갱신 | 규칙 승인, 장마다 확정 |
| 7 검수 | 기계 검사 + 대조표 | 검수 보고서(`references/templates.md` §4) | 대조표 승인 |
| 8 빌드 | 원본과 같은 방식으로 주입, 빌드 검증 | 빌드 산출물, 검증 로그 | **빌드는 지시받을 때만** |
| 9 회귀 점검 | 원본 대비 바뀐 것·위험 요소 표, 바뀐 것을 나눠 넣고 뺄 수 있게 | 위험 점검표 | — |
| 10 실행 검수 | 제보(스크린샷+상황)로 원인 조사, 같은 유형 전수 수정 | 수정 대조표 | 실기 확인 |
| 11 배포 | 버전 태그, 차분 패치/패처, README·라이선스 | 릴리즈 파일 | 공개 여부 |

## 단계별 핵심 규칙

**1 분석**
- 판정 기준: 텍스트 인코딩·태그를 다룰 수 있는지, 한글 약 2,350자가 폰트에 들어가는지, 그래픽 재압축이 가능한지, 체크섬·서명을 통과할 수 있는지, 분량이 현실적인지.
- 풀었다가 그대로 다시 묶은 결과가 원본과 바이트까지 같은지 먼저 확인한다. 같지 않으면 원인을 찾기 전까지 번역을 시작하지 않는다.
- 불가능·불투명이면 중단을 권하고, 배울 만한 구조·함정만 기록으로 남긴다.
- 진행한다면 분야 목록과 실행 환경을 확정한다(위 「적용 범위 정하기」).

**2 출력 시험**
- 배포 대상 환경에서 모두 확인받는다. 실기로도 배포한다면 실기 확인이 필수다. 에뮬레이터 정상이 실기 정상을 뜻하지 않는다.
- 실기가 없으면 정확도가 다른 에뮬레이터 두 가지 이상으로 보고, 「실기 미확인」을 기록한다.

**3 창 측정**
- 글자 수가 아니라 픽셀로 잰다. 폰트의 글자별 폭(고정폭 여부, 반각 문자 폭)을 확인한다.

**4 전수 추출**
- "전부"는 후보 목록으로 확인한다: 대사 파일, 스크립트·표·실행 파일 문자열, UI 텍스처, 배경 그림, 타일·스프라이트, 이펙트·파티클, 3D 모델, 영상(자막·로고). 게임에 없는 것은 「없음」으로 적어 빠뜨린 것과 구분한다.
- 다른 지역판이 번역한 곳은 화면에 나오는 곳이다. 다른 지역판도 그대로 둔 원문은 개발용일 가능성이 크다.
- 조사 범위를 표(대상·방법·개수·결과)로 보고한다. 빠진 영역이 있으면 스스로 밝힌다.

**5 번역**
- 용어집을 먼저 만들고 승인받는다. 공식 한국어 명칭이 있으면 따른다.
- 부호 규칙은 `references/style.md`를 따른다(마침표, 호격 쉼표, 말줄임표 뒤 마침표 금지, 괄호, 전각·반각).
- 번역 후 태그 보존, 줄 수, 창 폭을 기계로 검사한다.

**6 그래픽**
- 작업 전에 `references/templates.md` §3 규칙표를 채워 승인받는다(길이 차이 처리, 글꼴 느낌, 기울기, 테두리).
- 미리보기(원본 + 번역안) → 승인 → 작업 → 비교 시트(원본 | 지운 뒤 | 한글) → 확정.
- 글자 픽셀만 지운다(네모 금지). 지운 곳·새 글자 밖 변경 픽셀 0을 수치로 보고한다.
- 같은 그림·같은 시리즈는 묶어서 톤을 맞춘다. 확정본은 한 폴더, 목록 파일 하나에만 기록하고 동결한다.

**7 검수·10 실행 검수**
- 번역을 고칠 때마다 원문 | 수정 전 | 수정 후 대조표를 먼저 보여 준다.
- 제보 하나를 고치면 같은 유형을 전체에서 찾아 함께 고친다.
- 사용자가 화면에서 본 현상은 사실로 받고 원인부터 조사한다.

**8 빌드·9 회귀**
- 원본과 같은 압축·정렬·순서·헤더로 넣는다. 교체분 재확인, 나머지 원본 동일, 파일 크기 제한을 검증한다.
- 바뀐 것을 나눠서 넣고 뺄 수 있게 빌드해, 멈춤·크래시가 생기면 하나씩 빼서 원인을 좁힌다. 나누는 단위는 게임 구조를 따른다: 분야마다 파일·아카이브가 따로면 그 단위, 롬·이미지 하나면 빌드 옵션으로 분야를 켜고 끈다. 나눌 수 없으면 변경을 작게 여러 번 나눠 시험한다.
- 빌드·주입·기기로 옮기기(SD 복사·카트리지 쓰기 등)·커밋은 사용자가 시킬 때만 한다.

## 공통 원칙

- 분야 목록에 없는 것은 검사·추출·점검 대상에서 뺀다. 목록은 게임마다 1단계에서 정한다.
- 게이트에서 멈춘다. 판본·진행 여부·용어집·그래픽 규칙·번역 수정·빌드·공개는 사용자가 정한다.
- 상태는 목록 파일 하나에만 적는다.
- 지우기 전에 대상 목록을 먼저 보여 준다. 대괄호가 든 경로(`[Game]` 등)는 셸·glob 패턴으로 읽히므로, 남길 파일은 먼저 옮기고 지운다.
- 검증하지 않은 것은 검증하지 않았다고 보고한다. 실패는 원인과 함께 바로 알린다.
- 배운 형식 구조·함정·사용자 선호는 기록(메모리, `CLAUDE.md`)에 남긴다.
