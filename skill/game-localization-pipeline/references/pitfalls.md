# 실제로 밟은 함정

작품을 진행하며 겪은 문제와 해결이다. **해당 기종·형식·분야를 만났을 때만** 참고한다. 괄호 안이 해당 조건이다.

## 공통
- **무변경 왕복부터.** 추출 → 재조립 결과가 원본과 바이트까지 같지 않으면 이후 모든 문제의 원인을 가릴 수 없다.
- **에뮬레이터 정상 ≠ 실기 정상.** 실기로 배포한다면 출력 시험과 최종 확인을 실기에서도 한다.
- **덤프마다 해시가 다르다.** 같은 게임도 덤프·변환 도구에 따라 해시가 달라 통째 차분 패치가 안 맞는다. 파일 단위 차분으로 배포한다.
- **대괄호 경로.** `[Game]`, `[Wii]` 같은 폴더 이름은 glob·find·PowerShell `-Path`에서 패턴으로 읽힌다. glob.escape, `-LiteralPath`를 쓰고, 일부만 남길 때는 남길 파일을 먼저 옮긴다.
- **한글 경로.** 일부 도구(cygwin 계열 등)는 한글 절대 경로를 못 읽는다. 상대 경로로 넘긴다.
- **긴 한글 문자열을 셸 heredoc으로 넘기면 따옴표·줄바꿈이 깨진다.** 스크립트 파일로 써서 실행한다.

## 아카이브 (해당 형식을 쓰는 게임)
- **CPK(CRI)**: 원본에서 CRILAYLA로 압축돼 있던 파일을 무압축으로 넣으면 팩이 커지고 Wii U 실기(SDCafiine)에서 멈춘다. 에뮬레이터(Cemu)는 정상이다. 원본처럼 압축한다.
- **CPK**: 같은 내용 파일 여러 개가 같은 오프셋을 공유한다. TOC 기준 위치는 `min(TocOffset, 0x800, ContentOffset)`이다. ETOC 없는 CPK는 마지막 파일 뒤 패딩을 쓰지 않는다.
- **3DS romfs**: 다시 빌드하면 파일 배치가 밀려 거의 전체가 바뀐다. 원본 통째 차분은 비효율이다.
- **3DS LayeredFS**: 본편과 업데이트에 같은 경로 파일이 있으면 적용이 안 된다. CIA를 다시 만든다.
- **Wii 파티션**: 암호화 단위 때문에 1바이트만 바뀌어도 큰 구간이 달라진다. 파일끼리 비교하고 gzip은 풀어서 비교한다.

## 폰트 (폰트 파일에 한글을 넣는 게임)
- **고정폭 폰트**: 일본어 폰트는 반각 띄어쓰기·부호도 전각 폭인 경우가 있다. 한국어 번역에서 창을 넘친다 → 반각 글자 폭만 좁힌다.
- **기준선**: 한글을 셀 가운데 두면 원본 한자보다 위·아래로 치우쳐 첫 줄 윗부분이 잘린다. 원본 한자 잉크 아래끝에 맞춘다.
- **굵기**: 한자가 아니라 가나의 세로 기둥 굵기에 맞춘다(한자는 획이 빽빽해 기준으로 부적합).
- **축소 렌더**: 글자마다 따로 배율을 잡으면 획 굵기가 들쭉날쭉하다. 공통 배율·공통 격자로 그린다.
- **글리프 부족**: 번역에 실제로 쓰이는 글자만으로 아틀라스를 다시 짜면 대부분 기존 칸에 들어간다.
- **BC4 등 손실 압축 폰트**: 재인코딩 오차가 있으니 글리프 대조는 허용 오차를 둔다.

## 텍스트 (텍스트 파일을 교체하는 게임)
- **태그 표기**: 제어 코드를 사람이 읽는 표기(`[C:2]` 등)로 바꿔 번역 파일에 두고, 왕복이 원본과 같은지 확인한다.
- **줄 수 고정 창**: 설명창은 줄 수가 늘면 아래가 잘린다.
- **조각 치환**(스킬 설명처럼 정형 문장): 치환표는 긴 것부터 적용한다. 짧은 조각이 접두사를 삼킨다.
- **조사**: 변수·영문 뒤 조사는 발음 기준으로 고르거나 병기한다.

## 그래픽 (글자가 박힌 그림이 있는 게임)
- **숨은 글자**: 이펙트·파티클 파일(ptcl 등) 속 텍스처, 배경 그림 속 간판, 영상 속 글자를 놓치기 쉽다.
- **같은 그림 복사본**: 경로만 다른 같은 그림이 여러 벌 있다. 원본 해시로 묶어 한 번만 작업한다.
- **테두리·그림자**: 원본 글자의 테두리를 빼먹으면 밝은 배경에서 글자가 안 보인다. 원본 테두리 두께·진하기를 재서 맞춘다.
- **블록 압축(BC1/BC3)**: 바뀐 4×4 블록만 다시 압축하면 글자 밖은 원본 바이트 그대로 유지된다.
- **3D 모델 텍스처**: 규격대로 넣어도 실기에서 멈출 수 있다. 다른 묶음과 따로 넣어 시험한다.

## 영상 (영상에 자막·글자를 넣는 게임)
- **자막 굽기**: 원본 I프레임 위치에 키프레임을 강제하고 프레임 수를 맞춘다. 가장 큰 프레임이 원본보다 커지지 않게 품질을 조절한다.
- **투명도 영상**: 알파 스트림은 밝기 0~255 전체 범위일 수 있다. RGB를 거쳐 인코딩하면 16~235로 좁혀져 투명한 곳이 뿌옇게 된다. 밝기 평면을 그대로 굽는다.
- **타이틀 로고**: 로고가 영상 속에 있으면 정지 그림만 바꿔서는 일부 화면에서만 한글이 보인다. 영상을 넘겼을 때와 끝까지 볼 때를 둘 다 확인한다.

## 배포
- 패치에 게임 데이터를 넣지 않는다. 차분이나 패처로 배포한다.
- 크기가 유난히 큰 항목(예: 다시 구운 영상)이 있으면 선택 항목으로 나눈다. GitHub 릴리즈 첨부 파일은 하나에 2GB 미만이어야 한다.
- 릴리즈 첨부 파일 이름의 한글이 지워질 수 있다. 영문 이름을 쓴다.
- 폰트 라이선스(OFL 등) 전문을 함께 넣는다.
